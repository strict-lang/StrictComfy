# Diffusion inference in Strict: pending work
This file lists only what is still to be implemented: remove an item once it is done (results and numbers go into commit messages or a README), add what is found. Goal: ComfyUI's Moss (image DiT, RTX 3080) and MiniMax H3 (video+audio DiT, RTX 4090) in Strict faster than ComfyUI, on their own and through the ComfyUI nodes.

## Conventions
- Model specific Strict code and fixtures (`Moss*`, `H3*`, `Euler`, VAEs, `tinymoss.safetensors`) live here in StrictComfy, run with `../Strict/strict.exe test|build X.strict`; only generic pieces go into `../Strict` (other sessions work there too).
- `dump.py` (ComfyUI's `python_embeded`) writes reference dumps to `D:\StrictDumps\<name>` (`moss` with the DMD LoRA, `moss-base` without), prompt from `prompt.txt` (not checked in), 720 wide × 1280 high by default. `layer.py` recomputes layer 0 step by step in float32 torch from a dump (`layer0.safetensors`) to find where a port differs.
- Convrot int8 weights load as 8 bit packed rows whose per-32 scales all are the row scale (`Safetensors.Quantized`, exact) and run on the existing int8 tensor core path; activations are quantized per 32 numbers (ComfyUI: per token).

## Moss (RTX 3080)
- Resident backend: on 10 GB cards keeping the Moss weights on the GPU beats freeing them (Performance.md); a card that can not fit them next to ComfyUI's working set would evict them at job boundaries (`GpuMemory.Evicted`, like H3Video's resident mode).
- Node: negative conditioning for cfg above 1 (Strict guides against a zero prompt of the positive's length; another length needs its own rotation table).
- Runtime LoRA speed (5.3 s per image against 3.25 s merged): the LoRA epilogue (base + delta / Gain) fused into the expand `Products` (about 0.38 s per image of memory traffic), occupancy of the rank-128 down projection (split-K or a 64x128 tile), the per-image re-uploads (56/31/28 MB x 42).
- Grouped Modulated/Rotated vectorization, the full-size Rotated index miscompile, gate/modulation precision alignment.
- Merged LoRAs: per-32 scales for less rounding (stochastic rounding is approximate, 21-25 dB against runtime adapters). Spectrum: adaptive scheduling and ER-SDE are not covered (Spectrum.md).
- GEMM: no emitter change accepted yet, the analysis is in [GemmStalls3080.md](GemmStalls3080.md).

## H3 (RTX 4090)
- Steps: `best` 5.99-6.09 s against comfy_kitchen int8's 5.24-5.29 s per step of a 10 s clip (Readme.md); the gap is runtime work in ../Strict/improvements-gpu.md (dense attention, weight uploads not overlapped with compute, collections before activation blocks).
- LoRAs: merge time for big ranks (80 s for rank 384: join the factors without Strict list copies, more threads), an optional cache of the merged model on disk.
- HyperFlow's two-time `(t, r)` conditioning on pruned bases (the `comfyui-hyperflow-h3` node's experimental curve refit: `assets/curve_fits` per base, bound to its SHA-256, per block curve coordinates for the 16 trained `(t, r)` pairs and pinned `(t, t)` curves, gate 0.25; its fit reports 0.0058 error against 0.0137 for the backbone Strict runs now).

## Optimization (measured before/after)
- Elementwise work is the whole remaining Moss gap on the 4090 (`Performance.md`: 44.9 against ComfyUI's ~11 ms per step; GEMM, attention and Hadamard are level or faster, steps 187–194 against 223–261 ms). The loops already run at memory bandwidth, so fewer bytes: 16 bit intermediates (../Strict/improvements.md, 16 bit lists on the GPU) and fused passes (norm + modulation, q/k norm + RoPE, situ into the ffn_down quantization, gated residual into the GEMM epilogue), CUDA graphs per block; generated by the compiler or as calls into existing kernels is the user's decision. Range analysis for the divisions of generated loops (../Strict/improvements.md) before specialization machinery.
- Later: block-sparse attention (FastH3 gate), 0.2–0.3 MP preview paths, F8_E4M3 safetensors if a model needs it.

## Standalone H3Video
- Goal: `H3Video.exe` runs a ComfyUI workflow on its own (UI or API json: UNETLoader, LoRA loaders, CLIPLoader, MiniMax H3 Image to Video, Strict H3 Sampler or KSampler / SamplerCustomAdvanced, VAE Decode, VAE Decode Audio, Video Combine with NVENC) and replaces the slow parts with Strict code, the ComfyUI node stays.
- Order by overhead (2026-10-29, 480x832): the text encoder load for every run with a new prompt (28.9 s, ComfyUI keeps it in RAM; NVFP4 as 4 bit rows would read 15.7 instead of 27 GB; the strict-cd session), the video VAE decode and mp4 (5.3-5.9 s per 5 s video, 10-11 s per 10 s video; video and audio decode 4.2-4.9 s, ComfyUI warm 4.15 s and 0.4 s; per tile 17.4 ms int8 GEMMs at 75 % of the int8 peak, 15.0 ms attention in the generic kernel because the tensor core ones take only heads of 128 and the decoder's are 64 wide, about 0.7 s per 5 s video, 7.2 ms idle, 6.3 ms norms and scales, 4.2 ms RoPE; then the 1.3 s of bytes, wav and ffmpeg), the model load (6.4-11 s, TaoMate's merge 14-22 s) and VAE load (2.2-3.0 s), the image to video keyframe encode in the default GPU mode (12.5 s, 0.7 s with `STRICT_GPU=all`, the strict-cd session).

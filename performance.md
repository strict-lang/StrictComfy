- Moss steps on the RTX 4090 (704x1280, 115 ms, GPU busy all the time): int8 GEMMs 51 %, dense attention 19 %, the other 30 % are ten passes per layer over the 3557x3072 activations (Activated 6 %, Hadamard 6 %, Rotated 4 %, HeadScales 3 %, Gated 3 %, Modulated 3 %, values_transposed 2 %). Scales inside Rotated and Modulated would save a pass each.
- H3 Image VAE decode at 2048x2048 (done 2026-11-11): the image VAE's fp16 rows loaded as 32 bit floats and ran on `strict_device_blockss` at about 7 TFLOPS (714 of 814 ms GPU time at 1024x1024). `H3Decoder.Blocks` now loads them as 8 bit rows (`H3DecoderBlock.Loaded` bits, image VAE only): decode + jpg save 2.5 -> 0.6 s at 2048x2048, 0.76 -> 0.2 s at 1024x1024, 56 dB against the 32 bit decode. 16 bit rows gave identical pixels but were slower (3.2 s). Several tiles per pass was not needed.
- H3 Image sampling at 2048x2048 with a reference (edits, about 32k tokens): about 1.1 s per step against 0.55 s without; the 6 GPU-only steps stream part of the 21 GB model each step on a 24 GB card. A planned streaming set in the runtime would help (see the H3 Video notes in memory h3-sampler-streaming).
- H3 Image edit of a new image: the VAE encode of the input takes 2.0 s at 2048x2048 (121 `H3Tiles.Real` tiles, `H3Picture.Blended` and `Bytes` still on the CPU). `H3Tiles.Lean` (81 tiles) saves 0.5 s but changes the edit (30.5 dB), ComfyUI uses 256/64.
- `ImageCodec.SavePng` is stb on one thread: 0.3-0.6 s at 2048x2048, 2.5 s at 4096x4096, about 10 s at 8192x8192. Strips in parallel like SaveJpeg need deflate blocks that can be joined (stb writes one final block). The code is `../Strict/ImageProcessing/native/ImageCodec.c`.
- The first Moss step of every image takes 5-16 ms longer than the next ones.
